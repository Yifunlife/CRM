# 分批生产、装柜与发货

跟进表沿用现有甘特图、每项目一行和时间条小编辑框。有维护权限的人通过“新增批次”填写本批货物及数量，然后分别维护生产、装柜、发货的负责人、计划、状态、实际完成日期和执行依据。未排期环节通过“批次跟进”选择；不使用数量聚合块或展开全部流程行。

同一批按生产 → 装柜 → 发货完成；不同批次可并行。第一批发货不要求第二批生产完成，项目显示“已发1/2批”。全部批次生产完成才汇总为生产完成，全部批次发货完成才汇总为交付完成。整单归档和原执行入口不能跳过未完成的批次。

批次资料位于现有订单 `details.shipment_batches`，无需迁移或批量修改历史订单。原整单记录、付款、附件和商业版本保留。已有整单发货完成记录的订单不直接转换成分批模式。

接口：`GET/POST followup/orders/:id/batches`。写入复用本单维护权限、实际操作人、乐观版本、归档锁和审计记录。新增动作 `create`；更新动作 `phase`，只改指定批次的 `production/loading/shipping`。装柜完成要求柜号，要求验货的订单同时保留本批验货依据；发货完成要求运输或提单号，并沿用本单当前有效的付款/特批放行，免费补货沿用原发出批准。未解决的整单或本批对应环节待办会阻止完成。

主要验收：`scripts/test-followup-batches.mjs` 使用隔离数据库验证批次并行、完成顺序、权限、并发版本、放行、提醒、归档和原资料保留。`scripts/test-followup-gantt.mjs` 验证具名时间条和一项目一行。浏览器交互核对新增、保存、取消、并发冲突、只读权限和手机编辑框。
