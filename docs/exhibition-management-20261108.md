# 展会管理（2026-11-08）

入口为管理端「销售管理 → 展会管理」，延用现有 Fluent CRM UI。管理层、CEO、管理员在公司视角且具有全公司客资权限时可维护；业务员、运营、跟单员不能借助直接 API 访问。负责人来自实际在职管理层、CEO、管理员名单，停用后的历史负责人保留。

## 已实现

- 总甘特图包括2026年11月起八场展会。第一场2026美国展年份明确，另外七场按原截图月日暂列2027年并保留「年份待确认」。截图未提供的面积、展位号、各截止日、负责人、数量和费用留空，不引入原型示例数据。
- 每场支持展位面积、设计及物流截止日、预算、供应方、生产设备、流程起止/截止/下次跟进日、部门、负责人、进度与跟进记录。撤展阶段为当地出售设备。
- 七项准备清单独立勾选，记录确认人及时间。列表仅保留名称、数量、实际费用；点击名称用原地弹窗编辑。费用可叠加弹窗编辑，保存后更新原记录；取消与 Escape 仅关闭当前层。
- 提醒在展会页面计算：提前7/3/1天、当天和逾期事项，支持只看本人；展会设计/物流截止提前7天显示。不发送外部消息，不增加定时后台任务。
- 实际费用只在一套记录里登记；互动设备引用自制设备费用。出行费细分机票、住宿、打车、餐旅费。报价和预算不叠加实际费用。
- 设备当地出售在「费用与收入 → 收入明细」登记，记录设备/数量、买方、币种汇率、累计实收、交付及跟进信息。净投入=实际费用−设备出售实收，待收金额不抵扣。累计出售数量不能超过设备数量。
- 展会关联已有 CRM 客户和成交单。成交金额、有效实收与退款从现有 CRM 读取，按币种展示；一份成交单仅可归属一场展会。展会系统不改写原客户、成交单或收款记录。
- 展会资料按版本原子保存，每次写入保留审计；并发冲突拒绝覆盖，更新后保留用户弹窗草稿供核对。

## 数据与验证

新增 `crm_exhibitions`（版本化资料）与 `crm_exhibition_deals`（成交归属唯一约束）。迁移0044只新增表并填入八场展会和空白准备模板。未修改现有业务表。

通过展会专用数据库验收、权限验收、模块诊断、TypeScript及正式构建。本地浏览器核对桌面/393px手机、费用原地修改不重复、嵌套弹窗草稿、清单勾选及重载恢复、出行类别、当地出售实收抵扣、客户/订单搜索关联、Escape层级及无页面横向溢出。独立视觉验收结论为 ship，保留现有系统身份。

扩大检查时，`test-module-boundaries` 的旧定时器导入断言以及 `test-api-module-contracts` 的旧客资导入夹具失败；在未含本功能的 github/main 同样复现。未修改这些无关逻辑，也不将其描述为通过。

发布采用现有 Cloudflare Worker / D1 / R2 绑定与静态资源保留流程；不重建业务数据库，不生成桌面安装包。
