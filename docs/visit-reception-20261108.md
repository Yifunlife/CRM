# 客户到访登记与接待费用补填

已批准的紧凑接待表单接入“客户管理 → 到访记录”。常填资料在上方，行程、费用和到访后补充按需展开。人员使用在职员工名单；地点可选，其他地点可输入名称；到达和行程时间使用半小时下拉选项。标准七项行程可编辑、增减。

费用逐项记录预计和实际人民币金额；默认餐饮、交通（打车）、住宿，可增减。金额以十进制文本保存，汇总转换为整数分。实际留空为待补，零为未发生。接待显式标记完成后，每次到访若仍有待补费用，只在该接待业务员的“我的工作”显示一条提醒，列出待补类别。点击“去补填”打开同一记录、展开费用并定位第一项待补；保存全部实际金额后提醒消失，清空实际金额后恢复。未完成接待或没有费用项不产生提醒。

存储使用新增表 crm_visit_receptions，0045_visit_receptions.sql 仅新增表和索引。每次保存同时写 crm_sales_events 审计，并检查当前版本和客户归属，冲突不覆盖。保存接待计划不创建联系证据、不改变客户归属或收款。完成后的最新到访接入原客户到访视图；客户历史仅显示当前登记，费用修订审计不重复展示。历史导入与旧记录保留。接待表加入完整备份；合并最新主干时发现展会表未列入完整备份，也一并补齐了两张既有表的清单项。

客户负责人及既有管理权限可维护记录；被指定的接待业务员仅可访问其接待记录，不能更换客户或擅自转交接待。跟拍及陪同可选择实际在职员工，保留已停用员工的历史选择。角色只读验收继续阻止保存。导航保存精确 visit 标识，并使用既有未保存保护及安装草稿离页规则。

验证：test-visit-reception、test-personal-work、test-meetings-visits、test-unified-customer-archive、test-role-preview、test-sales-access、test-database-backup；TypeScript 与 Cloudflare 构建。真实本地页面使用隔离测试数据库完成登录、新建、保存、重新打开、半小时选择、地点/人员选择、费用补齐后提醒消除及清空后恢复、提醒精确跳转。修复日期控件 input 事件与保存值不同步的问题。手机 390px 视口下单列输入高度44px，页面无横向溢出，行程与费用表内部可横向滚动。

浏览器测试数据和测试账号仅存在于本地隔离数据库，没有向正式客户库导入。
