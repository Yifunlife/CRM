# 亦玩客资管理

第一版支持公司用户名/密码、管理员建号与停用、四类来源导入、运营批量分配、业务员独立客资视图、跟进历史、重复核查。暂不支持转交与各平台实时同步。

## 使用

管理员先在「账号与权限」创建运营和业务员，姓名与表格原业务员姓名一致。运营在「导入客资」选择来源与工作表，预览并确认。表格包含分配业务员时直接保留归属；创建对应姓名的业务员账号后自动关联客资，疑似重复也保留负责人。没有负责人的新增客资才进入待分配。VIP、A、B、C手动选择，未评级保留空值；分类看板按登录账号权限显示。

手机号仅按数字做疑似重复提示，不猜测国家区号。原始来源、需求、跟进状态及收件箱链接保存在详情里。完全相同的导入记录跳过，跟进不影响重复导入判断。

## 本地运行

需要 Node 22.13+。安装依赖后运行 `npm run build`，对生成的本地D1配置应用 `drizzle/0000_common_lorna_dane.sql`，运行 `npm start -- --port 8787 --var INITIAL_ADMIN_PASSWORD:<本地初始密码>`。首次登录 admin 创建管理员。正式初始密码通过 Sites 密钥配置，不写入源码。

数据库迁移：`node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_common_lorna_dane.sql`

## 验证

`npx tsc --noEmit` 验证类型；`python3 tests/workflows.py` 对一次性本地数据库验证权限与主要业务流程。测试不用于生产，重复运行前使用全新测试数据库。

## 托管与数据

Sites 使用 D1 保存账号、客资、分配和跟进，数据库不进入Git。站点入口允许持有链接者打开，公司账号登录后才可读取数据。登录会话12小时有效，停用会立即撤销会话。初始管理员登录后应修改密码。定期备份及独立域名待公司确定。

每次导入最多3000条，列表当前最多10000条；更大规模需增加服务器分页。无附件上传、客户删除、自动合并或跨平台聊天同步。表格文件在浏览器本地解析，确认后只提交所选工作表字段。

## 广告投放

管理员与运营可新增和更新投放记录，包括平台、广告名称、日期、负责人、进度、预算、实际花费和备注。阿里、抖音本地推固定使用CNY；Meta、谷歌固定使用USD。金额以整数分保存，汇总按币种分别统计，不自动换汇。业务员不可访问广告记录。已保存记录不能改到另一币种的平台，避免已有金额被重新解释。

验证：`node scripts/test-advertising.mjs`。
