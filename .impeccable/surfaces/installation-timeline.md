# 项目安装时间表与档案同步

## Scope and direction

既有订单安装计划的紧凑总览扩展，供有权限的商务和管理人员查看项目工期、分配师傅及核对接续。根 `PRODUCT.md`、`DESIGN.md` 继续定义产品与 Microsoft 365 浅色 Fluent 外壳；本表面继承白色工作面、Segoe UI 字体、蓝色操作和文字状态，不建立独立视觉体系。这里只记录本地实现及其约束，不代表生产发布或真实业务验收。

## Compact overview and editing

业务范围、安装交接状态及项目／合同号／国家／师傅搜索共用可换行工具栏。其下“师傅分配与工期”默认折叠，以项目数量及“展开编辑”说明入口；月度时间表为常驻主体，避免宽资料表挤占工期视图。

原17项资料继续保留（序号与项目名合并为首列）：序号／项目名、面积、国家、商务组别、设计组、工程组、是否有迷宫、计划到货、实际到货、签证类型、签证时长、安装人数、项目负责、安装出发、计划安装结束及备注。在同一张表中增加安装师傅、安装工期、转场天数及交接状态，共20列。安装人数、师傅、工期、出发／结束日期及转场可在有权限时编辑；每行明确“保存本行／取消”，未保存修改不冒充已同步。点击项目名进入原完整安装资料。

分配操作优先：前八列固定排序为项目、安装师傅、安装出发、计划安装结束、工期、人数、转场、交接状态，首屏直接填写师傅和排期。国家、迷宫、面积、负责人与原17项参考资料在右侧保留。项目名及参考值保持单行截断，完整内容可悬停或点项目查看，避免长名称撑高每行；未编辑行桌面约40px高。筛选与搜索控件统一高度、字号、内边距及上下对齐（桌面36px，手机44px）。

宽表在自身区域滚动（桌面总宽2180px、高度上限400px），只固定合并后的首列及表头。第二列保持普通数据列，不能恢复为叠加的固定列。日期、人数、天数和错误均保留文字；未知值使用“待确认／待安排”，原日期说明继续显示，不把说明推定为精确日期。

## Monthly timeline and project identity

时间表按日历天展示单个月份，提供上月、下月及“本月”；横向滚轮和鼠标横向拖动也可切月。切换相邻月份时列表回到顶部；拖动切月后阻止误触项目。项目名、时间条或空白轨道可打开同一个排期编辑器，点击轨道带入对应日期；演示模式点击进入示例完整资料，不写真实记录。

**The Interval Rule.** 月份筛选按时间区间相交判定，跨月项目保留。完全未排期项目在每月保留；仅有出发日期的项目从该月向后保留，仅有结束日期的项目向前保留。只有有效的起止日期才绘制完整时间条；只有当月出发日期时显示出发点及“结束待定”，其他不完整排期用文字说明，不补造结束日期。

项目编号由完整可见项目集计算，再用于筛选后的资料表、时间表和师傅列表。优先采用有效且不重复的原导入行号，其余按项目ID排序补用未占编号；同一项目集内切月、搜索和状态筛选不重新编号。编号不是独立持久化的全局项目ID，完整项目集合变化时回退编号可能变化。

项目使用15组鲜明底色／配套深浅文字循环配色，同项目编号和色彩在各视图保持一致；颜色表达项目身份，不表达业务阶段或完成状态。完整时间条文字从“编号 师傅”开始，接实际文字进度；窄条可截断，但保留开头识别信息及完整悬停说明。未分配师傅明确标记“待分配”，不凭颜色推断负责人。

## Layout and depth

桌面采用主时间表加185px师傅侧栏；1150px及以下侧栏为170px，900px及以下移到时间表下方。项目列依次为190px、170px，600px及以下为115px；手机仍保留项目名、剩余工期和师傅，允许辅助文字换行。月日刻度在手机只保留首尾、每周及当天重点，避免数字挤叠；日期仍保留语义时间标签。

**The Frozen Grid Rule.** 时间表滚动区域高度最多585px，并创建隔离层。顶部表头层级50、左上交叉角60、项目首列20、时间条及日期点2，今日参考线1；表头、角及首列必须有不透明背景。滚动时项目内容不能盖过表头或左上角。师傅列表也以585px为高度上限并自行滚动，项目多时不无限拉长页面。

时间条采用局部 `display:block`，保持从编号开头截断，避免继承按钮布局后在窄屏把开头挤出。最后一天的时间标签使用自身文字宽度并右对齐到末格，不能靠整行留白或隐藏末日修复边缘裁切。面板继续采用浅色面与细边界，固定表头的细底边用于区分滚动内容，不增加装饰性阴影。

## Remaining duration and crew continuity

计划出发优先取工厂安排日期，缺少时回退行程日期；计划结束取工厂结束日期，实际完成独立保留。工期优先显示填写天数，缺少时从有效起止日期按首尾均计的日历天推算。剩余天数是今天到计划结束日的日期差；当天为0天，超期显示“超计划 N 天”，安装已完成或已验收显示“已完成安装”。缺少结束日期显示“工期待确认”。这些数值不证明签证、机票、现场或客户条件已落实。

师傅姓名按顿号、逗号、分号、加号或换行拆分，使用当前权限内可见的项目及其他已读取安排计算，不能声称覆盖公司全部师傅。侧栏列出各师傅所有未完成分配，独立于当前月份和搜索结果，并显示各项目剩余工期与计划结束日。

最早接续日期取今天与各项目“计划结束日＋1天＋转场预留”中的最晚日期；未填转场时按1天计算，明确填0天有效。两个项目工期连同各自转场区间重叠时显示“含转场排期冲突”；任一未完成分配缺起止日期时显示“待补完整工期”，不提供可安排日期。可计算时“安排下一项目”带入师傅及接续日期，仍需选择项目并保存；它不自动确认可出行。

## Shared archive, authority and confirmation gates

时间表、资料表、项目档案和客户档案读取同一安装计划。订单及关联商务项目别名归一到同一规范项目记录；客户档案按规范记录去重，避免形成第二份工期。档案展示师傅、工期、剩余工期、计划／实际日期、转场、人数、负责人及进度，变更记录展开显示操作、师傅／工期快照、原操作人和时间；当前接口最多返回最近20条安装事件，不将其描述为无限完整历史。

保存沿用原安装安排事件及版本校验，追加计划快照并拒绝并发覆盖；成功后重新读取相应视图。读取、保存及失败均保留文字反馈，档案读取失败提供“重新读取”。页面内各视图共用持久记录，不承诺跨标签页实时推送。

**The Draft Is Not Confirmation Rule.** 快速编辑和逐行保存使用原工厂草稿动作。它们不会完成“确认人员并交接商务”、客户／出行准备、出票或验收；保存草稿会按原规则取消工厂／客户确认，已出票时要求行程重新确认，并重置安装完成／验收标记，原行程记录与历史仍保留。正式工厂确认继续核对工厂、师傅、人数、工期、可出发与起止日期、内部负责人及依据；出票继续要求人员、客户、现场、手续、费用确认齐全，验收继续要求已核实行程和完成依据。

读取继续遵守原客户、市场、订单及商务归属范围。工厂／排期维护以服务端 `can_factory` 为准：实际本人登录的管理员、CEO或销售管理层，且不属于个人业务账号、项目未归档；代看身份不可写入。商务准备、行程和验收使用原 `can_commercial` 权限及门禁。表格、弹窗和档案入口不能扩大资料归属或绕过服务端检查。
