# 分配管理页面约定

范围：`app/allocation-management.tsx`、`app/allocation-intake.tsx` 与对应局部样式。沿用 `PRODUCT.md`、`DESIGN.md` 和既有 Operate 紧凑后台，不建立新的全站视觉系统。

## 页面与视觉

- 使用现有深蓝导航、蓝色操作、浅灰蓝背景及白色面板；表格、筛选和清晰的文字状态优先。来源标签保留文字，Instagram、Facebook 和其他来源分别使用已有语义色。
- 顶部保留「分配总板」「导入表单」「分配记录」「分配规则」四个直接页签，不增加嵌套导航。分配总板内的客资列表可收起，统计区独立显示。
- 筛选与导入来源使用原生下拉选择器。导入页同时列出平台及账号按钮：内贸 3 个平台、7 个账号；外贸 4 个平台、8 个账号。其他客资渠道与社媒平台分组呈现，不计入社媒平台数量。
- 桌面筛选横向紧凑排列并允许换行；720px 以下改为单列，平台卡片与字段对应表堆叠。宽客资表格在自身区域横向滚动；页签可横向查看，分页与总数保留在表格底部。
- 状态提示使用文字与适当的 `status` / `alert` 语义；原生控件及按钮有可见焦点。统计数字支持鼠标、焦点和点击查看媒体明细，Escape 可关闭。

## 业务与交互边界

- 分配总板按业务范围、来源平台、来源账号、状态、原始提交日期和搜索词查看客资；日期口径为北京时间。默认开始日期为 2026-10-30，结束日期为当天；清空日期可查看全部日期。
- 运营默认进入内贸，导入默认「抖音 / 工厂号」，且只能导入内贸；其他具备分配管理权限的账号默认外贸「Instagram / 乐园号」。权限仍由既有服务端规则约束。
- Excel / CSV 导入先映射字段，再请求服务端去重预览，展示新增、重复或跳过、待核查与原负责人待匹配结果，最后明确确认导入。每次最多 3000 条。
- 保留原始字段、原表负责人以及已有来源平台和账号；页面选择只为缺失来源提供默认值。不同平台的同名账号分别记录，原负责人未匹配时保留原姓名。导入不自动分配；原文件不修改。
- 手动分配仅限符合条件的新客资：没有现负责人、原负责人或待核查标记，且不属于待接入记录。历史与待核查客资只展示。分配须先预览再确认，记录页保留分配、撤销及导入记录。
- 页面读取不修改既有原始客户资料。自动分配状态只如实显示，本页面的导入不启用自动分配。
- 「WhatsApp · 尾号 8111」只读取官方连接状态，提供状态刷新与接入说明。尚未完成官方号码授权及客资读取接通；不得将页面呈现视为授权完成或咨询接入可用。当前不启动历史读取、自动回复或自动分配。
