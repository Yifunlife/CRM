# 智能监控 · Sales Monitor

## Purpose and direction

为管理者提供全团队流程核查入口，为销售提供本人记录的处理入口。以已保存的客户、项目、报价、合同、订单和连接记录呈现问题依据、责任人、建议与原业务页面入口，帮助用户判断下一步。异常表示需要核查，不表示已证实业务失误。

沿用现有蓝白 Operate 操作后台，不建立新的视觉体系。全局品牌、导航、按钮与面板以 `DESIGN.md` 及现有后台为准；本文件只约束 `app/sales-monitor.tsx`、`app/sales-monitor.css` 这一表面。`PRODUCT.md` 保持不变。

## Layout and visual rules

- 内容区最大宽度 1320px，居中；标题“智能监控”、说明和“刷新监控”置顶。
- 首屏依次显示读取范围及北京时间、四项范围摘要、到期检查与报价来源状态，再进入“待处理事项”。摘要包括销售项目、执行中订单、新增待首次联系和异常事项；项目数按服务端返回的项目记录统计，不额外解释为活跃项目数。
- 待处理事项采用连续列表；每项先显示处理类型、流程环节与责任人，再显示标题、依据、建议和“去处理”。聚合事项显示记录条数。正文宽度不超过 75ch，长文本可换行，行动按钮不压缩。
- 类型与环节使用文字，只有异常额外使用红色 `#a62b26`，不能仅靠颜色表达状态。正文与次要文字沿用后台蓝灰色；摘要数字使用深蓝 `#183765`。白色面板、细分隔线承接现有后台。
- 筛选依次为处理类型、流程环节、负责人（仅全团队范围）和搜索；搜索匹配事项标题、依据、负责人，不承诺搜索所有业务字段。修改任一筛选返回第一页。
- 每页 30 项，多页时在列表底部显示页数、事项总数和前后页按钮。列表数量表示事项数；聚合事项中的“条”表示业务记录数，两者不混用。
- 团队处理分布置于列表之后；人员按钮显示待核查事项数与异常事项数，点击切换对应负责人筛选，重复点击恢复全部。分布数据来自完整返回结果，不随当前类型、环节或搜索筛选重新计数。
- “监控依据与处理规则”默认折叠，展开提供数据、刷新、提醒时间、历史归属和原页面审批规则。
- 局部面板间隔 24px；桌面筛选四列，720px 以下改两列、标题和事项行动纵向排列，380px 以下筛选改单列。窄屏事项及人员按钮至少 44px 高。按钮、搜索框和下拉框提供 2px 蓝色可见键盘焦点。

## States and interactions

| 状态 | 界面行为 |
| --- | --- |
| 初次读取 | 显示读取提示，容器 `aria-busy`，刷新按钮显示“正在读取…”并禁用。 |
| 成功 | 显示范围、北京时间读取时间、真实来源状态及当前结果。进入页面与手动刷新触发读取；无轮询承诺。 |
| 首次失败 | 显示 `role="alert"` 错误及“重新读取”入口，不展示虚构结果。 |
| 刷新失败且已有结果 | 保留上次成功结果及其时间，并明确显示“当前显示上一次成功读取的结果”。 |
| 报价来源不可用 | 展示服务端“未配置”或“暂时无法读取”，并提示待接收报价可能不完整；不能据此宣称没有待接收报价。 |
| 最近检查无记录 | 显示“尚无记录”；不将读取时间当作每日检查完成时间。 |
| 筛选无结果 | 提示调整筛选；保留筛选控件。 |
| 已接入记录无事项 | 明确限定为当前已接入记录中没有匹配事项，不宣称全业务健康。 |
| 去处理 | 将事项交给既有 `openItem` 导航逻辑，在原业务页面处理。 |

## Data and permission boundaries

`lib/sales-monitor.ts` 提供只读 `GET sales-monitor`。服务端允许 sales、admin、ceo、management 角色，并按既有能力权限约束范围；前端隐藏负责人筛选不替代服务端授权。管理能力范围读取全团队，销售读取本人客户与项目、本人商务负责订单；团队分布仅在全团队结果中返回。

事项优先级为异常、待确认、到期提醒、待处理、历史对齐。来源包括新增客资首次联系、项目下一步、报价同步与接收、合同交接与订单关联、现有付款/特殊放行申请、已生成站内通知，以及已启用 WhatsApp 连接状态。连接检查只提示核查，不代发消息。

刷新只读取当前记录，不新建业务、重新生成到期通知或执行审批。到期提醒来自已存储的站内通知，每天北京时间 08:00 检查；08:00 后到期的事项在下次检查处理。读取时间与最近日检查时间必须分别呈现。

历史客资归属待对齐单独列示，不计入新增分配、待首次联系或首次联系逾期。未归属的聚合事项以管理者为处理提示，不能伪装为已分配给某位销售；团队人员分布不包含这类无人员归属事项。

报价接收、合同与跟单负责人确认、付款确认及 CEO 特殊放行继续使用既有业务页面及权限。监控页不增加批准、保存、自动修复、分配、消息发送或历史数据变更入口。
